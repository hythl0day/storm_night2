# 《暴风夜》第二季 规则修订计划

> 目标：在重制节目（千问 → Kimi）之前，基于 rules-6 / rules-8 文本与 run1、run2 两次完整对局的实际表现，完成一轮规则修订，使规则更严密、更平衡、更适合 AI 玩家执行，并更适合剪辑成短视频节目。

---

## 1. 修订目标

1. **严密性**：消除规则文本的漏洞与矛盾，减少主持人临场裁定（前两局中临场裁定非常多，是记录混乱的主要来源）。
2. **平衡性**：解决两局共同暴露的结构性问题——侦探权力过大、部分职业强弱失衡（机制池的冗余是特性，见 3.3，不以使用率论去留）。
3. **可执行性（AI 友好）**：规则表述要让 AI 玩家不误解、不遗忘；通过流程设计减少"技能捏到死都不用"和"复读式发言"。
4. **观赏性**：节奏不拖沓、谋杀有仪式感、结局有高潮、记录格式天然防剧透、便于后期剪辑。

## 2. 前两局复盘要点

### run1（反派胜，4 天）

- 杀手桑娜 + 帮凶杰米娜零损失获胜。平民在第 2 天夜里就已经完整推理出真相（智谱），但仍然输光。
- 第 2、3 天最关键的调查权都落在帮凶杰米娜手里：她当众伪造监控记录，再用【信号干扰】把谎言"做实"，是全局胜负手。
- 平民方两个【看破伪装】+【犯罪侧写】**全程零使用**，是最大的自废武功。
- 查特在第 3 天亲历地下室谋杀（房间只有他、智谱、桑娜），却在第 4 天辩护时完全没抛出这个一击必杀的排除法，握着答案被投出局。
- 千问（Qwen）表现最差：复读发言、公开自报体格 1、主动邀请杀手留宿。

### run2（记录止于第 4 天投票前，大概率平民胜）

- 杀手狄西第 1 天当众宣布"保险箱里的化学试剂我先保管"，第 2 天偏偏用这颗全世界知道在他手里的毒药杀人，证据链一步锁死。
- 帮凶桑娜以侦探身份"大义灭亲"带节奏投出搭档，随后用【舞台魔术】当着杰米娜的面杀智谱——但"意外"的目击结论等于职业签名，一夜之间被排除法锁定。
- 记录**没有结局**（最终投票、遗言、身份揭晓全部缺失），且存在多处连续性错误（手电筒复活、案发房间前后矛盾、名字写成"智璞/仟文"）。

### 两局共同结论

1. **反派侦探是前两局最强的"职业"**——谁拿到侦探位，谁就控制了调查与叙事。
2. **机制利用率极低**：两局的谋杀手段分别是手枪+舞台魔术、毒药+舞台魔术，环境凶器、空手谋杀、夜间入侵、窃听器、赠送道具等大量机制从未登场。
3. **主持人裁定与记录规范是最大的工程问题**，比平衡性更伤节目。

### 3.2 平衡性问题（P1）

1. **侦探权力过大且无制衡**（两局共同的最大问题）：指定调查员 + 独家看监控 + 分配战利品道具 + 规则明文允许公布假情报，且人选纯靠行动顺序碰运气。run1 帮凶靠它获胜，run2 帮凶靠它垄断叙事。
2. **调查员由侦探指定**，反派侦探可以永远绕过犯罪侧写师（run2 桑娜跳过智谱），侧写师两局零使用、形同废人。
3. **魔术师作为反派的两极表现**：
   - run1：【舞台魔术】无视一切防御、不罚目击，一击必杀无反制；
   - run2："意外"目击结论 = 职业签名，案发即暴露。
     说明目击结论的设计需要重做，而不是简单加强或削弱。
4. **黑客作为反派偏强**：开锁、停电、改监控三位一体，一人完成全部操作链（run2 狄西）。
5. **毒药的情报负收益过大**：鲁米诺验出"死于毒药"= 官方认证反派专属道具 + 来源是保险箱，比用刀的指向性强太多。
6. **魔术师/机械师的反派被动（失去非停电空手谋杀）只惩罚了这两个职业**，其他职业当反派没有等价代价，不对称。
7. **"须超过半数才出局"是巨大杠杆**（run1 杰米娜 3/6 票存活直接改变结局）。本身是好设计，但要意识到它让"弃权和分散投票"成为平民的慢性自杀——可与发言/投票引导机制联动。

### 3.3 关于"未使用机制"的修正结论：冗余是特性，不是缺陷（P2)

> 本节按"抽卡选片"方针修正：超出单局容量的职业/道具池是**刻意设计**，目的是让每局配置组合不同、提高抽卡的随机性。因此"前两局没用到"**不构成**删除理由。每个职业/道具的去留按三个标准审查：
>
> 1. **规则完善性**：文本是否无歧义、可被主持人（或引擎）机械裁决；
> 2. **剧情潜力**：被 roll 到时，能否独立产出至少一个高光场景；
> 3. **理性可触发性**：roll 到之后，一个理性的 AI 玩家是否真的会用它（被严格压制的机制即使出场也是死重）。

按这三个标准全量审查（明细见附录 A），结论是：

- **10 职业、14 道具全部值得保留**，无一需要删除；6 处需文本修补（见 3.1 与附录 A），仅【舞台魔术】的目击结论需要重新设计（见 4.2）。
- 真正的问题不在"池子太大"，而在**可触发性**：空手谋杀的体格/性别条件体系两局从未生效（反派永远优选武器杀，条件体系只在停电/黑暗中才接管）——这本身可作为"稀有分支"接受，但夜间入侵的风险收益不成比例（开锁能力稀缺、失败即暴露），需要按 4.3 补强，否则它即使被 roll 到也永远不会发生。

### 3.4 AI 执行与流程问题（P2)

1. **技能闲置**：看破伪装、犯罪侧写两局几乎零使用。需要在流程上设置"必须决策的时点"（如发言阶段开始时主持人逐一询问是否发动技能），而不是等 AI 自己想起来。
2. **规则性谎言无人抓**：run2 狄西"我昨晚在监控室查看记录"（当时无任何案件记录可查）是一句规则上不可能成立的谎言，主持人和 5 个 AI 全部漏过。主持人手册需要一份"规则合法性校验清单"。
3. **复读与注水**：同一 AI 的发言隔天逐字复制；空话套话多。需要在 prompt 层限制（引用新证据、禁止重复上一日论点）。
4. **记录格式混乱**：系统提示混入叙事、多视角"你"无标注切换、人称/名字不统一、技能台账与正文不一致、结局缺失。这是节目素材的硬伤，详见 §5。

## 4. 修订建议（方案稿，待讨论）

### 4.1 P0：规则文本修补

直接修订 rules 文本，把 §3.1 的 11 条全部写死。重点条款：

- **死亡公告**：任何谋杀（含未遂）在其发生的时间阶段结束时立即公告；白天案件公布房间，细节留待次日调查阶段。
- **出局揭示**：投票出局后立即公开其身份（平民/帮凶/杀手）与职业；帮凶继任杀手不公告，但主持人私下确认；出局者遗言在身份揭示**之前**（保留悬念，遗言可以是谎言）。
- **看破伪装范围**：明确只能验证"职业、道具、技能、行踪"四类声明，"我是不是凶手"不在范围内（保留诈唬空间，但写进规则让所有人知情）。
- **无杀规则**：改为"自首起谋杀发生后起算，连续两个完整天无谋杀则平民胜；谋杀未遂重置计数"（给反派喘息，也给未遂以价值），并删除与第 1 天禁杀的叠加歧义。
- **道具次数**：逐个道具标注使用次数；明确"收走→投票后分配→次日可用"的时间线。
- **监控语义**：写明只记录进入、不记录离开，且主持人在公布监控时只陈述记录本身。

### 4.2 P1：平衡性改造（三个方向，建议 A）

**方向 A：削侦探、放调查（✅ 已选定）**

- 监控改为：案发后**全员可见原始记录**（主持人公开宣读），侦探的特权改为"额外多查一个时间段/场所"。反派改监控的技能保留，但篡改结果对所有人生效——风险与收益对等。
- 调查员改为自荐制：所有有调查技能/道具的角色都可各自调查并**私下**从主持人处获得结果，自行决定是否公开、是否撒谎。取消侦探指定权。
- 道具分配改为公开讨论 + 投票决定（侦探仅有平局裁决权）。

**方向 B：保留强侦探，但改产生方式**：每日投票选出侦探（可以被选者拒绝），反派当侦探是平民的失误而非运气。
**方向 C：最小改动**：只修继任时点（新侦探即时生效，旧侦探不跨案），其余不动。

配套调整：

- **舞台魔术重做目击结论**：保留"无法被急救箱/闪避反制"，但目击结论改为"凶手是在场者之一，且魔术师本人不被排除"——去掉"意外"这个签名，也去掉"必然嫁祸成功"。
- **魔术师/机械师的反派被动统一化**：改为所有职业当反派时，非停电空手谋杀都需要满足体格/性别条件（即现状），魔术师/机械师的补偿是技能本身；不再额外剥夺。
- **毒药**：鲁米诺验毒的结果改为"死于利器/钝器/毒/枪击"四选一中的"不明物质（毒或药物）"，不直接点名"毒药"道具，给反派留一层辩护空间。
- **黑客**：【信号干扰】明确一次只能改一条记录；或改为"改一条、但监控室当晚的进入记录对所有人生效可见"（风险化）。

### 4.3 P2：提高可触发性 + 节目节奏（不删减机制池）

> 以下改动不删减任何职业/道具，只让那些"roll 到也不会被理性使用"的机制变成可选路线。

1. **空手谋杀激活**：黑暗（停电/地下室）中体格条件放宽已有；再增加"目标处于睡眠/独处卧室时体格条件 -1"，让夜间入侵成为可行路线（配合开锁能力）。
2. **环境凶器**：书房雕像、地下室电线改为**不限次数但会留下独有伤痕**（现场调查可直接锁定案发房间），从"一次性彩蛋"改为"高风险路线"。
3. **赠送道具**：在公共发言阶段增加一个固定的"交换环节"（30 秒），降低使用门槛。
4. **节奏保险（✅ 已定为"主神胜利"）**：保留"无杀倒计时"但按 4.1 修改（自首杀起算、未遂重置，已确认）；第 5 天结束时若仍无阵营达成胜利，则**全员失败、主持人（主神）获胜**——保证 5 天内必出结果，利于分集剪辑，同时强化"主神"的叙事人格。
5. **8 人局与主谋**：暂缓（✅ 已确认本季以 6 人局为主，阵容=六家顶尖 AI，Kimi 顶替千问席位）。rules-8 的主谋机制留作后续赛季的扩展包。

### 4.4 P3：AI 执行层（主持人手册 + prompt 工程）

1. **主持人手册**：开局清单、每阶段流程清单、规则合法性校验清单（监控语义、看破范围、谋杀条件）、连续性台账模板（道具/技能次数/伤亡）。
2. **玩家 prompt 模板**：每人每轮收到统一的局面简报（公开信息 + 你的私密信息 + 你的技能剩余次数 + 本阶段可做的全部动作列表），并要求发言必须"引用至少一条新证据，不得重复上一日论点"。
3. **强制决策点**：每个阶段开始时，主持人逐一私聊询问有可用技能的 AI "是否发动"，把"遗忘"变成"明示放弃"。
4. **规则全量公开（✅ 已确认）**：完整规则书发给所有玩家（全量职业/道具目录是推理与 Bluff 的空间，绝不能只发本局实际出现的子集），私有的只有身份、职业、道具分配和私密事件。
5. **选拔池无跨局记忆（✅ 已确认）**：正片选拔池每局独立，轮回感由剪辑赋予；带记忆的连续对局留作后续"老兵赛季"企划（届时发布顺序必须=实际对局顺序）。

## 5. 节目制作配套（记录格式即剪辑工程）

前两局的记录格式问题会直接决定后期成本，建议本季把"记录规范"当作规则的一部分：

### 5.0 叙事框架：第一人称主角 + 人狼村式轮回（✅ 已选定）

- 节目以单一角色的第一人称视角呈现，参考人狼村（Raging Loop）：主角开局是"被直接杀死的小白"，随剧情逐步学会规则。**观众不需要任何开场规则讲解**——每条规则由剧情事件带出，观众和主角一起学。这从根本上解决了"观众跟踪不了 10 职业 14 道具"的问题：观众只需要学会当周目用到的规则。
- **抽卡 = 轮回**：多局抽卡可以编排为同一主角的多个"周目"——按"主角死得多早/多惨"排序发布，前期是主角被秒杀的教学集，后期是主角逐渐掌控全局的复仇集。由此，抽卡的"废品局"不再是废品：主角死得惨的局恰恰是前期最好的素材。
- 选片标准因此更新：第一标准是**主角弧线**（死亡/存活方式是否有教学价值或反转价值），其次才是整局精彩度。
- 录制要求：POV 角色的私密记录必须完整，且 prompt 中要求该角色输出**内心独白**（行动理由、怀疑对象、情绪），作为第一人称旁白素材；后期可补写，但需标注为演绎。
- 待确认：主角人选、"轮回记忆"的设定，见 §7。

1. **分线记录**：每个 AI 的私聊与视角单独存档，主线记录只含公开事件；旁白/系统提示与叙事文本分离（不同标记），剪辑时可一键剥离剧透信息。
2. **防剧透结构**：台账（谁有什么道具）绝不放在文件开头；身份揭晓统一放在结局。观众视角建议采用 run1 教训得出的方案——**前两集平民视角（悬疑），第 3 集起切换全知视角（希区柯克式俯视悬念）**，或全程藏身份到结局，二选一，需在录制前定。
3. **谋杀仪式感**：谋杀发生时主持人用固定格式的"事件卡"描述（时间/地点/目击者听到的声音），保证每场谋杀有可剪辑的素材，而不是一行流水账（run2 "狄西对千问使用了毒药"）。
4. **结局仪式**：固定流程——最终投票 → 遗言 → 身份逐一揭晓 → 复盘独白（胜方/败方各一段）。run2 连结局都没记录，本季必须写进流程清单。
5. **连续性台账**：道具、技能次数、房间锁状态由主持人每阶段更新并归档，杜绝"手电筒复活"这类穿帮。

## 8. 工程架构（跑局管线，✅ 方向已确认）

### 8.1 统一编排器，不接入各家官方 CLI / 通用 agent 环境

自研 Python 编排器直接调用六家 API，AI **不**使用各自的 CLI 或 shell。理由：

1. **公平性**：六家共用同一套工具与 prompt 脚手架，差异只来自模型本身。"AI 智斗"的卖点要求排除 harness 差异——官方 CLI 的工具能力各不相同，谁赢会变成"哪家 harness 强"而不是"哪家模型强"。
2. **信息隔离**：通用 shell 无法阻止 AI 偷看他人私聊、主状态文件、甚至开局脚本输出。本游戏的核心是信息隔离，AI 只能看到编排器按阶段下发的内容。
3. **自动化**：抽卡需要批量跑 10 局，六套异构 CLI 无法稳定编排、无法结构化存档。

AI 侧接口最小化，每阶段输入四件套：① 静态精简规则书（全量）；② 角色私密卡；③ 本阶段局面简报（增量）；④ 本阶段合法动作菜单。输出 = 自由文本发言 + 结构化动作（JSON，可校验、可拒绝非法动作）。

### 8.2 文件协议：共享目录可行，但由编排器托管

用户设想的"同一目录共享文件"方案可行，但**读写范围必须由编排器按阶段严格控制**，不能依赖文件系统权限（Windows 上尤其不可靠）。推荐：AI 通过 API 消息收发，编排器落盘成以下结构，文件作为存档与后期素材：

```
game-<id>/
  seed.txt            # 随机种子：可复现，兼作"对局未被操纵"的凭证
  state.json          # 主状态（仅编排器可读写）
  rules.md            # 本局使用的规则书快照
  public/             # 公开日志：公告、发言、投票、监控公布、死亡公告
  private/<player>/   # 私密卡、私聊记录、个人调查结果、该玩家的内心独白
  inbox/<player>/     # 本阶段简报（编排器生成）
  outbox/<player>/    # 该玩家的发言与动作回执
```

上下文控制：规则书压缩至 ~2-3k tokens；简报每阶段重生成（增量 + 台账摘要，不全量重发）；每个 AI 维护自己的 `notes.md`（私有），跨阶段复读自己的笔记而非全量日志。

### 8.3 开局生成脚本

`deal.py --seed N --players 6`：随机分配身份（4 平民/1 帮凶/1 杀手）、职业（10 选 6）、道具（14 选 6，杀手/帮凶必得武器）、首日行动顺序、保险箱内容；输出 `state.json` + 六张私密卡 + `rules.md` 快照。种子可复现：同 seed 可重跑同一局，用于调试与公平性自证。

### 8.4 接入层：混合渠道兼容（✅ 已确认可行）

现状：ChatGPT / Claude / Gemini / GLM 走中转站，DeepSeek / Kimi 走官方 API + key。编排器按"provider 适配层"设计：

- **协议收敛**：中转站、DeepSeek 官方、Kimi（Moonshot）官方三者均提供 OpenAI 兼容的 `/chat/completions` 接口，因此**一个 OpenAI 兼容客户端 + 每个玩家独立的 `base_url` / `api_key` / `model`** 即可覆盖全部六家。若个别模型需要原生接口（如 Claude 走中转站表现不佳），适配层预留 Anthropic 原生协议实现，按玩家配置切换。
- **配置文件驱动**：`players.toml` 逐席位声明 `{名字, base_url, api_key 环境变量, model, temperature}`，换阵容只改配置。
- **不依赖原生 tool calling**：结构化动作通过"纯文本 JSON 输出 + 编排器解析校验"实现，避免中转站对 function calling 支持不一的坑；解析失败自动打回重试。
- **鲁棒性**：中转站稳定性参差，编排器内置超时、重试、断点续跑（每阶段落盘后可从 state.json 恢复）；逐席位记录 token 用量与原始响应存档。
- **公平性**：温度等采样参数六席统一；每局的 `players.toml` 快照随 `game-<id>/` 归档，阵容与参数可追溯。
