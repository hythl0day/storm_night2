# 自研跑局环境（Orchestrator）开发计划

目标：替代人工主持，全自动批量跑局（抽卡），产出结构化、防剧透、可直接用于剪辑的对局素材。

## 0. 工程架构（跑局管线，✅ 方向已确认）

### 0.1 统一编排器，不接入各家官方 CLI / 通用 agent 环境

自研 Python 编排器直接调用六家 API，AI **不**使用各自的 CLI 或 shell。理由：

1. **公平性**：六家共用同一套工具与 prompt 脚手架，差异只来自模型本身。"AI 智斗"的卖点要求排除 harness 差异——官方 CLI 的工具能力各不相同，谁赢会变成"哪家 harness 强"而不是"哪家模型强"。
2. **信息隔离**：通用 shell 无法阻止 AI 偷看他人私聊、主状态文件、甚至开局脚本输出。本游戏的核心是信息隔离，AI 只能看到编排器按阶段下发的内容。
3. **自动化**：抽卡需要批量跑 10 局，六套异构 CLI 无法稳定编排、无法结构化存档。

AI 侧接口最小化，每阶段输入四件套：① 静态精简规则书（全量）；② 角色私密卡；③ 本阶段局面简报（增量）；④ 本阶段合法动作菜单。输出 = 自由文本发言 + 结构化动作（JSON，可校验、可拒绝非法动作）。

### 0.2 文件协议：共享目录可行，但由编排器托管

AI 通过 API 消息收发，编排器落盘成以下结构，文件作为存档与后期素材：

```
game/<id>/
  seed.txt            # 随机种子：可复现，兼作"对局未被操纵"的凭证
  state.json          # 主状态（仅编排器可读写）
  rules.md            # 本局使用的规则书快照
  public/             # 公开日志：公告、发言、投票、监控公布、死亡公告
  private/<席位id>/   # 私密卡、私聊记录、个人调查结果、该玩家的内心独白
  inbox/<席位id>/     # 本阶段简报（编排器生成）
  outbox/<席位id>/    # 该玩家的发言与动作回执
```

上下文控制：规则书压缩至 ~2-3k tokens；简报每阶段重生成（增量 + 台账摘要，不全量重发）；每个 AI 维护自己的 `notes.md`（私有），跨阶段复读自己的笔记而非全量日志。

### 0.3 开局生成脚本

`deal.py --seed N --players 6`：按阵容配置选出本局席位并生成**角色表**（名字/性别/体格/人种，全员公布），随机分配身份（4 平民/1 帮凶/1 杀手）、职业（9 选 6）、道具（车道制，见下）、首日行动顺序、保险箱内容（开局公告公开）；输出 `state.json` + 角色表 + 六张私密卡 + `rules.md` 快照。种子可复现：同 seed 可重跑同一局，用于调试与公平性自证。

deal 的车道分配与平衡保证（v3.2，全部论证见 docs/v3.2-plan.md；公开规则写入 rules-6 §2）：
1. **车道分配**：杀手=凶器+「万能钥匙」；帮凶=凶器+随机 1 件反派道具（裹尸袋/可疑的粉末/病毒U盘——纯毁证类，螺丝起子已移出）；平民 4 人=保底凶器（枪/刀/棍）1 人 +「螺丝起子」1 人（不同人）+ 通用池抽 2 人。**四凶器严格必现**：保险箱抽中反派道具时，第 4 件凶器直接发给剩余平民之一。不明药剂药毒两用；武装指认口径枪/刀/棍。
2. **保险箱随机化+公开**：从「剩余凶器+剩余反派道具」抽 1 件，内容随开局公告公开——书房成为争夺焦点，"保险箱产出反派道具"稀释有罪道具实锤。
3. **反派功能覆盖保证**（保密）：反派队至少一人持 {舞台魔术/延时装置/记忆植入/信号干扰} 之一（破抱团或破票仓）；不满足时杀手与首位持该类职业者确定性互换（无随机后处理）。停电源已由万能钥匙保底（v3.2 拉电闸），不再依赖职业。
随机调用顺序见 deal.py docstring（计入 seed 语义，勿随意调整）。

### 0.4 接入层：混合渠道兼容（✅ 已确认可行）

现状：ChatGPT / Claude / Gemini / GLM 走中转站，DeepSeek / Kimi 走官方 API + key。编排器按"provider 适配层"设计：

- **协议收敛**：中转站、DeepSeek 官方、Kimi（Moonshot）官方三者均提供 OpenAI 兼容的 `/chat/completions` 接口，因此**一个 OpenAI 兼容客户端 + 每个玩家独立的 `base_url` / `api_key` / `model`** 即可覆盖全部六家。若个别模型需要原生接口（如 Claude 走中转站表现不佳），适配层预留 Anthropic 原生协议实现，按玩家配置切换。
- **配置文件驱动**：`players.toml` 逐席位声明 `{名字, base_url, api_key 环境变量, model, temperature}`，换阵容只改配置。
- **不依赖原生 tool calling**：结构化动作通过"纯文本 JSON 输出 + 编排器解析校验"实现，避免中转站对 function calling 支持不一的坑；解析失败自动打回重试。
- **鲁棒性**：中转站稳定性参差，编排器内置超时、重试、断点续跑（每阶段落盘后可从 state.json 恢复）；逐席位记录 token 用量与原始响应存档。
- **公平性**：全席统一不发送 temperature（部分中转站上游只接受默认温度，干脆统一口径）、max_tokens 全席统一；每局的 `players.toml` 快照随 `game/<id>/` 归档，阵容与参数可追溯。


## 1. 设计原则

1. **公平**：六个席位同一套接口与 prompt 脚手架，差异只来自模型。
2. **信息隔离**：AI 只能看到编排器按阶段下发的内容，不接触文件系统。
3. **机器可裁决**：规则全部编码进引擎；AI 的自由文本只管"说"，状态变更只认结构化动作 JSON。
4. **可复现**：每局一个 seed；同 seed 同参数可重跑（用于调试与公平自证）。
5. **素材即存档**：运行日志天然就是 `public/` + `private/` 分线素材。

## 2. 模块划分

| 模块 | 职责 |
| ---- | ---- |

| `orchestrator.py` | 主循环：按阶段生成简报 → 收集各 AI 输出 → 校验动作 → 推状态 → 落盘 |
| `prompts/` | 模板：规则书注入、私密卡、阶段简报、合法动作菜单、发言/独白要求 |

| `src/scorecard.py` | 评分卡（M6 修订）：只读扫描对局存档目录（默认 game/，--dir selected 扫精选池），单局报告（台账/流程简报/戏剧性评分/主角弧线候选/成本）+ 多局报告（版本分组胜率/机制利用率/多样性/成本汇总）。批量跑局器（batch.py）已取消——单局一小时以上，手动换 seed + 断点续跑更稳 |

## 3. 关键接口

**players.toml**（每局归档快照）：
```toml
[[player]]
name = "奇米"          # 角色名（规则书阵容表）
model = "kimi-k2"
base_url = "https://api.moonshot.cn/v1"
api_key_env = "MOONSHOT_API_KEY"
temperature = 1.0
# ... 共 6 席
```

**AI 每阶段输入四件套**：精简规则书（全量静态）+ 私密卡（身份/职业/道具/剩余次数）+ 阶段简报（增量公开事件 + 仅自己可见的私密事件）+ 合法动作菜单。

**AI 输出**：自由文本发言 + 动作 JSON，例如：
```json
{"speech": "……", "inner": "内心独白（不公开，仅存档）", "actions": [{"type": "enter_room", "room": "地下室"}, {"type": "invite", "target": "查特"}]}
```
非法动作 → 驳回并要求重报（不公开驳回事实）；JSON 解析失败 → 自动重试（上限后记为放弃行动）。

**内心独白**：每阶段强制输出，作为第一人称视角的旁白素材（POV 叙事框架依赖它）。

**角色扮演层**：每个角色配一份固定人设卡（性格、口癖、行事风格、背景故事），跨周目保持一致，作为节目品牌资产。发言模板强制要求：引用至少一条具体证据、明确表达立场与情绪、不得重复上一日论点、禁止空泛套话。戏剧性集中在 `speech` 与 `inner` 通道释放，`actions` 保持冷静合法——演出与决策互不污染。

## 5. 风险与对策

- **中转站稳定性**：超时/重试/断点续跑（每阶段落盘）；某席位连续失败时允许该局作废重跑。
- **上下文膨胀**：简报只发增量 + 台账摘要；每 AI 维护私有 `notes.md`，跨阶段复读笔记而非全量日志。
- **JSON 合规率**：动作菜单给足示例；解析失败重试；最坏情况降级为"仅发言"。
- **规则边界**：M3 单测以规则书 §7/§9 为准逐条覆盖；引擎裁决日志全量存档，供赛后审计。
- **成本**：单局 token 预估后设定 batch 预算上限；测试期用低价模型占位。
