# 自研跑局环境（Orchestrator）开发计划

目标：替代人工主持，自动跑完整对局（手动换 seed 抽卡），产出结构化、防剧透、可直接用于剪辑的对局素材。当前主线为 6 人局 v4.0；批量自动跑局器已取消，单局运行与断点续跑由 console / orchestrator 承担。

## 0. 工程架构（跑局管线，✅ 方向已确认）

### 0.1 统一编排器，不接入各家官方 CLI / 通用 agent 环境

自研 Python 编排器直接调用各家 API，AI **不**使用各自的 CLI 或 shell。阵容池目前为 8 席，每局选 6 席。理由：

1. **公平性**：所有席位共用同一套工具与 prompt 脚手架，差异只来自模型本身。"AI 智斗"的卖点要求排除 harness 差异——官方 CLI 的工具能力各不相同，谁赢会变成"哪家 harness 强"而不是"哪家模型强"。
2. **信息隔离**：通用 shell 无法阻止 AI 偷看他人私聊、主状态文件、甚至开局脚本输出。本游戏的核心是信息隔离，AI 只能看到编排器按阶段下发的内容。
3. **自动化**：统一管线才能稳定推进多阶段对局、校验结构化动作并生成可直接分析的存档。

AI 侧每阶段输入四件套：① 本局规则书快照（full 或 lite）；② 角色私密卡；③ 本阶段局面简报（增量事件、台账与自己的 notes）；④ 本阶段合法动作菜单。输出为 `speech`（公开发言）、`inner`（私密内心独白）、`notes`（跨阶段私人笔记）与 `actions`（结构化动作 JSON）。

### 0.2 文件协议：共享目录可行，但由编排器托管

AI 通过 API 消息收发，编排器落盘成以下结构，文件同时作为断点存档与后期素材：

```
game/<id>/
  seed.txt            # 随机种子：复现初始 deal，不保证 AI 后续输出可复现
  deal.json           # 初始状态快照，供 replay 分叉重建
  state.json          # 当前主状态（仅编排器可读写）
  rules.md            # 本局规则书快照（rules-6.md 或 rules-6-lite.md）
  players.toml        # 本局阵容与 API 参数快照（不含真实密钥）
  personas.toml       # 本局人设快照
  script.md           # 主持人侧全记录，含剧透，不含内心独白
  host_log.jsonl      # API 成败、延迟与 token 台账
  public/             # 公告、公开发言、投票、监控公布等公开口径
  private/<席位id>/   # 私密卡、私密记录、notes 与内心独白
  inbox/<席位id>/     # 每次席位调用的简报
  outbox/<席位id>/    # 原始响应、动作与可选 thinking 存档
  replay.json         # 仅 replay 分叉存档：来源与分叉节点
  interview/          # 仅录制采访后生成：问答与当次记忆档案
```

上下文控制：简报按阶段重生成，以下发增量与台账摘要为主；每个 AI 维护自己的 `notes.md`，跨阶段复读笔记而非依赖完整对话历史。公开与私密事件分别进入 `orch.feed` / `orch.hist`，供简报、采访和查看器使用。

### 0.3 开局生成脚本

`deal.py --seed N --players 6`：按 `players.toml` 与 `personas.toml` 选出本局席位并生成全员公开的**角色表**（名字/性别/体格/国籍），随机分配身份（4 平民/2 杀手）、职业（8 选 6）、道具、首日行动顺序和保险箱内容；同时输出初始/当前状态、六张私密卡及规则与人设快照。随机选席默认维持中美 3+3，对称无法实现的手动阵容只提示。

deal 的 v4.0 车道分配与平衡保证（公开规则见 `rules-6.md` §2）：
1. **反派车道**：两名杀手各得刀/棒球棍/不明药剂中互不重复的一件；随机一名杀手另得「万能钥匙」，另一名另得「可疑的粉末」或「木马程序U盘」。职业纯随机，不再做反派功能职业保底或身份互换。
2. **平民车道**：随机一名平民固定得「螺丝起子」；其余平民从通用道具池与未分出的反派道具中抽取。保险箱抽中反派道具时，剩余凶器改发给一名平民。
3. **桌上与保险箱**：会客室桌上固定放「左轮手枪」，首任侦探当选后取得；保险箱从剩余凶器与剩余反派道具中抽 1 件并随开局公告公开。四凶器严格必现，武装指认可用武器为枪/刀/棍。

随机调用顺序见 `deal.py` docstring，计入 seed 语义，勿随意调整。同 seed + 同参数可复现的是初始分配，不是整局 AI 行为。

### 0.4 接入层：混合渠道兼容（✅ 已确认可行）

编排器通过 `src/providers.py` 按席位配置切换协议，具体渠道与模型以项目根 `players.toml` 为准：

- **协议适配**：OpenAI 兼容 `/chat/completions` 与 Anthropic 原生 `/v1/messages` 均已实现；每个席位独立配置 `base_url` / `api_key_env` / `model` / `api_type`。
- **配置文件驱动**：`players.toml` 只保存环境变量名，不保存真实 API key；每局归档阵容与参数快照。
- **不依赖原生 tool calling**：结构化动作通过纯文本 JSON 输出与编排器解析校验实现，避免不同渠道 function calling 能力不一；解析失败自动打回重试。
- **鲁棒性**：内置连接/停滞/总墙钟超时、流式回退与指数重试；席位行动完成后落盘，可从 `state.json` 断点续跑，逐席位记录 token、延迟和原始响应。
- **公平性**：所有请求不发送 temperature；`max_tokens` 与 `reasoning_effort` 由 `[settings]` 统一定义、席位可覆盖，个别上游不兼容时按配置例外不发。


## 1. 设计原则

1. **公平**：所有席位使用同一套接口与 prompt 脚手架，差异只来自模型。
2. **信息隔离**：AI 只能看到编排器按阶段下发的内容，不接触文件系统。
3. **机器可裁决**：规则全部编码进引擎；AI 的自由文本只管"说"，状态变更只认结构化动作 JSON。
4. **可复现**：每局一个 seed；同 seed 同参数可复现初始 deal，用于调试与公平自证。
5. **素材即存档**：运行日志天然分为 `public/`、`private/` 与主持人侧全记录，剪辑时可按信息线取材。

| `src/replay.py` | 存档分叉：目标前复用原始 outbox 重建状态，到指定席位调用前另存，随后由 console / orchestrator 续跑 |

## 3. 关键接口

**players.toml**（每局归档快照）：
```toml
[settings]
max_tokens = 16384
reasoning_effort = "low"

[[player]]
id = "kimi"
name = "奇米"
model = "..."
base_url = "..."
api_key_env = "..."
api_type = "openai"  # 或 "anthropic"
# ... 当前阵容池共 8 席，每局选 6 席
```

**AI 每阶段输入四件套**：本局规则书快照（full/lite）+ 私密卡（身份/职业/道具/技能）+ 阶段简报（增量公开事件、私密事件、台账与自己的 notes）+ 合法动作菜单。

**AI 输出**：四通道 JSON，例如：
```json
{
  "speech": "……",
  "inner": "内心独白（不公开，仅存档）",
  "notes": "留给后续阶段的私人笔记",
  "actions": [{"type": "choose_room", "room": "地下室"}, {"type": "invite", "target": "查特"}]
}
```
非法动作 → 私下驳回并要求重报；JSON 解析失败 → 自动重试，上限后按当前环节约定降级或放弃行动。

**内心独白与笔记**：`inner` 是第一人称旁白素材；`notes` 是跨阶段记忆，二者都不公开。`speech` 承担公开演出，`actions` 保持冷静合法，演出与决策互不污染。

**角色扮演层**：`personas.toml` 是性别/体格/国籍与性格底色的权威来源；失忆开局不写传记或预设职业，性格只通过言行自然流露，不限制模型推理能力。发言模板要求引用具体证据、明确立场与情绪、避免重复和空泛套话，并限制各通道篇幅。

## 5. 风险与对策

- **渠道稳定性**：连接/停滞/总墙钟超时、流式回退、指数重试与席位断点续跑；某席位持续失败时可暂停排障或作废该局。
- **上下文膨胀**：简报以增量和台账摘要为主；每 AI 维护私有 `notes.md`，跨阶段复读笔记而非全量日志。
- **JSON 合规率**：动作菜单给足示例；解析失败或非法动作私下重报，最坏情况按环节约定降级为仅发言或放弃行动。
- **规则边界**：改规则时同步规则书、引擎、编排器菜单/简报和测试，并更新 `deal.py` 的规则版本；裁决日志全量存档供赛后审计。
- **平衡漂移**：full/lite 与不同规则版本分池统计；通过真实跑局持续观察胜率、谋杀频率、机制利用率和消极局比例。
- **成本**：单局调用次数随密谋与环节增加而上升；用 `host_log.jsonl` 与 scorecard 跟踪 token、缓存、失败率和延迟，手动控制跑局节奏。

## 6. 依赖与前置

- 当前引擎以 `docs/rules-6.md` 为准；lite 只改变 AI 可见规则信息，不改变裁决。
- 所需 API key 通过 `players.toml` 中配置的环境变量注入，真实密钥不写入仓库或对局快照。
- Windows + Git Bash，Python 3.11+；运行依赖只有 `httpx`，CLI 渲染使用手写 ANSI，未引入 rich 等 TUI 库。
