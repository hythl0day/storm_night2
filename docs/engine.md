# 引擎文档（src/engine/）

规则裁决引擎（M3）。**纯逻辑库**：不调用 AI、不做网络请求、不打印；输入是 `state` 字典 + 玩家声明的动作，输出是结构化事件。编排器（M4）负责收集 AI 输出、调用引擎裁决、按"公开/私密"分发结果。

## 1. 模块划分

| 模块 | 职责 |
| ---- | ---- |
| `state.py` | 状态装载与扩展字段（`ensure()` 幂等初始化，含旧档技能键迁移）、房间/黑暗/门锁/监控/台账等共享助手、`load_state`/`save_state` |
| `murder.py` | 谋杀判定（§7.6/§7.7）：条件校验、自卫矩阵、延时装置设置与触发、舞台魔术、凶案发现者台账落账（v3.30）、黑暗房间不设人数限制与会客室桌上凶器临时取用（v3.31） |
| `vote.py` | 投票结算、记忆植入、帮凶继任、武装指认（v3.5 侦探垄断）、侦探竞选与佩枪授予、遗嘱落账（v3.5 当天可用/未指定拒收回桌） |
| `ledger.py` | 开锁/保险箱/赠送/停电/发电机/监控/调查/伪造/移尸/侧写/看破伪装/封闭空间/密道/窃听器/取桌上物品（v3.5） |
| `core.py` | `Engine` 类：阶段流转（翻日轮转、清晨公告、倒计时与主神判定）、`unlock_for_entry` 独立开锁轮、昼夜统一进入与开锁者优先（v3.26）、`finish_room_entries` 收尾 |

## 2. 事件契约

所有裁决方法返回统一结构：

```python
{"ok": bool, "type": "murder" | "vote" | ...,   # ok=False = 非法动作被驳回，状态不变、不公开
 "public": ...,      # 所有人可见的公告内容
 "private": {...}}   # 仅特定玩家可见的信息（供编排器按席位分发）
```

非法动作（次数耗尽、条件不满足、阶段不符）被驳回时**不改变任何状态**且驳回事实不公开（对应规则书 §9.8）。

## 3. 公共 API（Engine 方法）

阶段与流转：
- `advance()` — 推进到下一阶段；翻日轮转行动顺序、清晨公告（昨日死亡与未遂——**v3.22 起死亡/未遂不再阶段末即时公告，公告不含事发时段；v3.30 起有报案人时一并刊出（案件置 announced）**/职业/监控宣读——**v3.22 覆盖案发当日全天两个时段**/封存道具 + 状态行：存活数/无杀倒计时/封存数 + v3.5 桌上物品变动 + 已永久开启台账；存活侦探列名提醒）、第 4 天门锁全开、无杀倒计时与主神胜利判定
- `engine.winner` — `None` / `"平民"` / `"反派"` / `"主神"`
- `unlock_for_entry(user, room, assignments)` — v3.26 独立开锁轮：只为本人已声明的目标房间消耗一次手段并开门，不移动玩家；随后由进入轮统一结算
- `choose_room_one(name, room)` / `finish_room_entries()` — 自由活动单人进入的低层入口与收尾；进入时不再自动开锁，满员/无人开门/被封闭空间挡住者滞留会客室；`finish` 落结算标记并统一判定延时装置
- `enter_rooms(assignments, invited=None, unlockers=None)` — 白天统一进入：开锁者优先，其余按行动顺序；`unlockers={房间: 开锁者}`，None 为测试默认（视同候选者均愿意），显式空 dict 表示无人开锁
- `night_assign(assignments=None, invited=None, unlockers=None)` — 晚间使用同一套开锁与进入顺序：合法去向=自己卧室（默认）/他人卧室/会客室/书房/监控室/地下室；他人卧室上锁（需开锁轮或受邀）；容量与白天一致（3/2/3/2/不限）；**平民慎入**（平民非受邀进入已有他人的功能房→失败回卧室；被邀请者与反派豁免）；失败者默认回自己卧室；结算后统一判定延时装置

谋杀：
- `murder(killer, target, weapon=None, savior=None)` — 空手/凶器/环境凶器裁决；`savior` = 同房用急救箱/不明药剂（药用）施救者
- `set_device(user, room)` — 机械师【延时装置】设置（第 1 天禁止）
- `stage_magic(user, target)` — 魔术师【舞台魔术】（占用当阶段谋杀机会；v3.30：在场者当场只知奇怪动静、不知是谋杀）

投票：
- `resolve_vote(votes, implant=None)` — `votes={投票人: 目标|None(弃权)}`；侦探一票计 1.5（v3.3）；`implant={"by":..,"voter":..,"target":..}` 为记忆植入改票
- `armed_accusation(accuser, suspect, weapon=None)` — 武装指认（v3.21 淘汰制）：投票结算后、出局执行前发动——① 未产生出局者的投票后；② 投票将导致**最后一名平民**出局时该平民在出局执行前（`resolve_vote(defer_out=True)` 把出局写入 `pending_out`，窗口关闭后由 `execute_pending_out` 或指认完成结算）。收益：指对→被指认的**杀手出局**（`_execute_out` 与投票出局共用：封存/身份公布/帮凶继任；帮凶已不在则反派全灭平民胜）；指错→指认者出局（公众可推知所指非杀手）。仅限平民；有侦探时仅侦探本人且须持武器；无侦探时持武器平民可指认，桌上凶器仍在时平民可临时取用指认。武器口径 = 枪/刀/棍，不含不明药剂。每次投票至多一次（`accusation_fired_day` 引擎级守卫）；**v3.22：指认消耗武器（等同攻击）**——自己的武器扣次数销毁（`weapon` 可指定，缺省取口径顺序第一件），临时取用的桌上凶器用掉即从桌上移除、不再放回；出局者遗言/遗嘱与投票出局同流程（编排 `_accuse_aftermath`）
- `elect_detective(ran, stay, votes)` — 侦探竞选裁决（v3.3：仅第 1 天竞选时段一次；平票/无人报名/全员参选则本局无侦探）；v3.5 当选时桌上凶器归侦探（侦探佩枪，公开公告）
- `bequest(owner, mapping, replies)` / `bequest_badge(owner, to, accept)` — 遗嘱制（v3.5）：封存道具逐件指定归属、接收人可拒收、**接受当天即可用**；未指定/拒收的道具不销毁，放回会客室桌上；警徽同走遗嘱（拒收/未指定则销毁，不补选；佩枪是普通道具，随遗嘱/缴获正常流转）

房间与道具台账：
- `unlock(user, room)` / `open_safe(user)` / `transfer(giver, receiver, item, accept=True)` / `use_flashlight(user)`
- `declare_blackout(user)` / `fix_generator(user)` — 停电声明窗口 = 公共发言/投票阶段，或自由活动阶段选房结算开始前（首个进入落定后以 `selection_begun` 驳回，rules-6 §7.5"阶段开始前声明"）；成功记 `blackout_news`，由编排器在选房收尾后公开公告（"进入房间后向众人公布"）；**停电持续至 `fix_generator` 为止——无人修复则跨日延续，不会自动恢复**（AI 侧公告/菜单/回执均已明示）；v3.11 起编排器在选房阶段向每位进入者私密送达「停电发现」回执（逐人发现，后续选房者无法从进入结果推断停电；选房简报也不再标注锁状态，锁台账由简报「游戏状态」段的「已永久开启」承载）；v3.23：`blackout_news` 非空期间（已声明未公布）「游戏状态」段供电行一并隐藏——此前选房者能从供电行提前得知停电
- `take_table_item(user, item)` — v3.5 取桌上物品：仅晚间休息、身处会客室且室内无其他存活者；物品保留剩余次数、当夜即可用；变动记入 `table_events`，次日清晨公告
- `place_bug(user, room)`（可放会客室——唯一能听到大厅交谈的手段）/ `bug_listen(user)`（v3：晚间休息在卧室收听，×2 次）
- `seal_room(user, allowed=None)`（建筑师【封闭空间】，不能对会客室；第 4 天门锁全开后仍可用）、`set_passage(user)` / `use_passage(user, room)`（v3.22 密道：仅晚间休息，出口会客室/书房/监控室/地下室任选，进入条件=谋杀人数条件，失败不损毁，成功一次后损毁；经密道进会客室者不上夜宿名单）

监控与调查：
- `view_monitoring(user)` — 查看公开监控（篡改后的口径）；v3 起恒为全量返回（不接参数，杜绝格式幻觉）；v3.5 起监控覆盖所有房间门口（含会客室）
- `tamper_monitoring(user, period, room, op, name, new_name=None)` — 【信号干扰】/「病毒U盘」，`op` ∈ `add`/`remove`/`replace`
- `investigate(user, case_id, choice)` — 【现场调查】/「鲁米诺试剂」，`choice` ∈ `武器伤痕`/`死亡时间`/`尸体转移`
- `falsify(user, case_id, kind)` — 伪造类反派技能（`kind` 区分伪造痕迹/销毁证物/伪造证物）；v3.18：须身处案发现场（场外反派不可远程毁证，编排侧毁证窗口同样只通知案件房间内的反派）；v3.19：仅限案发当天（次日清晨调查后现场即无法改动；归宿选择时的毁证提示**v3.22 起仅发给案件凶手本人**——死亡不再即时公告，其他反派无从得知案发）。AI 侧案件指认 = 受害者名字（`case` 字段，编排层解析为内部 id；回执回显受害者与房间）
- `move_body(user, case_id, to_room)` — 【转移尸体】/「裹尸袋」；v3.18：同样须身处案发现场；v3.19：同样仅限案发当天
- `profile(user, case_id, aspect)` — 【犯罪侧写】，`aspect` ∈ `性别`/`国籍`/`体格`
- `see_through(user, target, claims)` — 【看破伪装】/「测谎仪」，以**真实**监控记录验证行踪声明（v3.5 起所有房间可验证；无效房间名仍为"无法验证"）；v3.12：存在停电空白时行踪"无记录"判"无法验证"而非谎言/属实；claims 全为非法名目整体驳回不消耗次数；房间字段容错接受单字符串

## 4. 状态扩展字段

引擎在 deal.py 产出的 state 上扩展（完整注释见 `state.py` 模块 docstring）：

`locks`（门锁，卧室键 `"<名字>的卧室"`）、`safe_open`、`table_items`（v3.5 会客室桌上物品 `[{name, uses_left}]`，deal 写入初始桌上凶器）/`table_events`（待清晨公告的桌上变动）、`positions`、`monitoring`（公开口径）/ `monitoring_true`（真实记录，仅宿主）、`skill_uses`、`cases`（案件：伤痕/死亡时间/移尸/伪造状态/封存 + v3.30 `announced`（清晨已公告）/`discovered_by`（发现者，host 侧）/`reported_by`（报案人，清晨刊出））、`attempts`（未遂记录）、`last_murder_day`、`winner`/`win_reason`、`detective`、`stage_murder_used`、`power_out`、`blackout_days`（拉闸声明日，停电次数统计）/`blackout_periods`（实际监控缺失时段，含跨日延续与修复当日）/`power_restored`（最近修复时点）、`blackout_news`（待公告的停电时段）/`selection_begun`（选房已开始标记，关闭停电声明窗口）、`flashlight_lit`、`bedroom_relock`（被他人开锁的卧室下一阶段复锁）、`sealed_room`、`passage`/`passage_stealth`（密道使用者不留监控记录）、`bug_room`、`devices`（延时装置）、`sealed_items`、`profession_public`、`last_vote`。

玩家道具栏从 `item` 扩展为列表：`player["items"] = [{"name", "uses_left", "available_day"}]`——支持杀手缴获多件、遗嘱/桌上取用当天即可用（v3.5）、转手不改变次数；deal 可用 `extra_items` 额外配发（杀手的固定万能钥匙、帮凶的固定反派道具），ensure 时并入。

门锁口径（v3.5 rules-6 §3.1/§5）：书房/监控室/地下室的门与保险箱打开后永久开启；卧室被他人开锁后下一阶段复锁；会客室夜锁每天重新落下（第 4 天起全开）；停电期间门锁失效（保险箱除外）。

## 5. 裁决细则备忘（规则书未明说处的实现裁定）

1. 舞台魔术占用当阶段谋杀机会（它"就是一次谋杀"）。
2. 自卫武器不消耗次数；急救箱/不明药剂（药用）/敏捷闪避触发即消耗（目标同时持有急救箱与不明药剂时优先耗箱）。**待拍板**：如需"自卫也耗武器"改 `_defense` 一处即可。
3. 第 1 天禁止设置延时装置（与全天禁杀一致）。
4. 持枪者被枪击时不能以枪自卫（"枪←无效"）。
5. 犯罪侧写体格：≥3 报「健壮或魁梧」，否则报「普通或瘦弱」（v3.20：直接按角色表文字口径，弃用易混淆的「强壮/普通」标签——game/838823 克劳德误把魁梧排除在「强壮」外）。
6. 伪造类技能的假结果取确定性值（伤痕取下一项、死亡时间取另一时段、移尸取反）；每起案件只生效一次伪造。
7. 残局收束（v3.14/v3.15）：删去"只剩 1 平民反派直接胜"的全部即时判定——规则回归"杀光/票光所有平民"一句话；票仓锁死的残局（如 2v1）由下一轮投票自然了结（至多一天"行刑日"），1v1 决斗（含平民侦探 1.5 票反杀）保留；主神死线从第 5 天晚间移至**第 6 天终审投票后**（v3.15：第 6 天只有白天会议，无自由活动/晚间休息），作为对反派"须全灭平民"的时间补偿。v3.13 曾把 ≤1 平民判定上收进 check_winner（game/31 复盘的垃圾时间修复），v3.14 认定该规则本身不值保留而回滚；票仓判定方案经讨论放弃（规则难以理解，不如延长一天简单）。
8. 记忆植入直接改写选票，公告只说"票数被更改过"。
9. 延时装置的"拆除"规则书未定义动作，未实现（需要补规则后再加）。
10. ~~夜袭/守夜拦截/空房白跑~~（v3.22 删除）：晚间休息与自由活动同构（见 `night_assign`）——卧室夜间黑暗（`is_dark` 阶段感知：晚间休息阶段卧室视为黑暗）、谋杀每阶段独立一次机会（白天成功不再占用当夜机会）、卧室满 2 人天然挡住后来者（含杀手）、平民慎入有人的功能房；守夜邀请泛化为"同入邀请"（任意目的地，成立=邀请者已安置在同一房间）。
11. v3.22 密道：进入条件与谋杀人数条件同（亮房非反派 ≤1、暗房 ≤2），故密道永远不能撞进人堆；出口有人但不超条件时可进入（杀手可借道谋杀，由编排器房间行动窗口提供）；出口含会客室（亮房条件；不上夜宿名单）。
12. v3.26 统一开锁与进入：昼夜均先收齐去向，再对每扇目标房门按行动顺序私密询问拟进入者；首位愿意者消耗一次手段并成为开锁者。开锁轮不移动玩家；进入轮由开锁者优先，其余按原行动顺序，顺序靠前但无手段者不再被提前劝退。容量、邀请、封闭空间、平民慎入与失败回退均在进入轮照常判定；白天靠后者只看到先前的去向声明，晚间声明仍互不可见。延时装置仍在全员进入后统一判定。
13. v3.5 桌上物品：取用判定为"归宿结算后会客室仅此 1 名存活者"（含夜宿者——夜宿名单次日公开，独宿取物等于自首）；停电不放宽独处要求（会客室永不黑暗）；盗贼道具回桌后反派夜里仍可取回（自取无害）。
14. 黑暗房间交谈（v3.17/v3.22 统一口径）：亮房正常交谈；黑暗房间仅"同入邀请成立的组合"（互知在场）可摸黑低语——全体在场者（含看不见的潜伏者）都能听到，低语者不知是否被旁听。守夜密谈（卧室受邀组合）与会客室围炉夜谈（亮房正常交谈）均由同一套 `room_talks` 分发，组合资格按阶段取 `free_invites`/`night_invites`。
15. 黑暗房间中，**反派（杀手与帮凶）仍能知道在场者的具体身份**，谋杀/舞台魔术菜单据此提供目标名；这只是人员信息例外，黑暗的行为不可见、交谈限制、人数条件与空手豁免均不变，帮凶仍无普通主动谋杀权。平民仍不知道黑暗房间内有谁；**同入/守夜邀请成立时对邀请者私密可见**（黑暗中也知道应邀者到来；未成立则无通知），受邀者因主动选择同房故天然知晓。
16. 房间行动每人每轮只能选择一个动作（v3.25）：一次申报多个动作整批驳回、私下重报一次，不先执行其中任何动作；修复发电机也只是普通单动作，不附带修后补问或额外谋杀机会。
